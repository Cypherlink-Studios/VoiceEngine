# Design: Enhance Velocity Plugin Hot-Reload and Command Aliases

## Context

See `proposal.md` for motivation. In `VoiceEngineVelocityPlugin`, `reloadPlugin()` reloads configuration from `velocity-config.yml`. However, WebSocket client reconnection previously only checked if `voiceConfig.voiceServerUri()` differed from the current client's URI. Furthermore, `VelocityTokenManager` stored an immutable TTL, preventing dynamic token lifetime updates without restarting the proxy.

## Goals / Non-Goals

**Goals:**
- Detect changes to `secret-key` or `voice-server-url` during reload and safely restart the backend client.
- Dynamically apply new token expiration periods (`token-ttl-minutes`) to subsequent tokens generated by `VelocityTokenManager`.
- Provide `/ve`, `/voiceengine`, and `/audio` aliases across all Velocity voice commands via Incendo Cloud annotations.

**Non-Goals:**
- Invalidating existing active tokens before their natural expiration when TTL is changed.
- Sending reload signals from Velocity down to Paper backend servers (Paper plugins have their own `/voice reload` if needed).

## Decisions

### 1. Reconnection Criteria in `reloadPlugin`
- **Choice**: Compare both `backendClient.getURI().equals(voiceConfig.voiceServerUri())` and `backendClient.getSecretKey().equals(voiceConfig.secretKey())`.
- **Rationale**: Rotating the shared secret on the voice server requires the proxy to authenticate with the new token. Failing to reconnect leaves the socket running with the old secret until a restart.
- **Alternatives considered**: Always reconnecting on reload regardless of changes. *Trade-off*: Closes a healthy socket unnecessarily if the admin only changed messages or notifications.

### 2. Mutable Token TTL in `VelocityTokenManager`
- **Choice**: Make `tokenTtl` a `volatile Duration` with a thread-safe setter `setTokenTtl(Duration)`.
- **Rationale**: Generating tokens is concurrent (multiple players running `/voice`). A `volatile` reference provides instant visibility to all threads without requiring synchronized blocks or locks.
- **Alternatives considered**: Recreating the entire `VelocityTokenManager` instance on reload. *Trade-off*: Would wipe pending tokens that players haven't yet redeemed in the web client.

### 3. Command Aliases using Incendo Cloud
- **Choice**: Update the Cloud command literal strings from `"voice ..."` to `"voice|ve|voiceengine|audio ..."`.
- **Rationale**: Incendo Cloud's `@Command` annotation natively supports pipe-separated syntax for root command aliases, automatically generating parser trees and tab completions for `/voice`, `/ve`, `/voiceengine`, and `/audio`.

## Risks / Trade-offs

- **[Risk] Socket recreation failure during reload** ? Mitigation: Preserve existing client or log a descriptive warning if the new URI/secret fails validation before shutting down the old client.
