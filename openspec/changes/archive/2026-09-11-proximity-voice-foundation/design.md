## Context

VoiceEngine enables zero-mod proximity voice chat for Minecraft players by bridging a PaperMC server with a browser-based WebRTC client. See `proposal.md` for motivation and background context.

The system is constrained by:
1. Pure vanilla Minecraft client compatibility (no client-side mods, forge/fabric loaders, or custom resource pack sound manipulation).
2. Browser security constraints (microphone access strictly requires HTTPS/WSS and an explicit user interaction event to resume the browser `AudioContext`).
3. Real-time networking requirements (smooth positional audio requires 10-15 Hz updates with client-side interpolation; server CPU must scale across dozens of simultaneous voice streams).

## Goals / Non-Goals

**Goals:**
- Provide an out-of-the-box monorepo setup containing the Paper plugin, the Node.js Mediasoup SFU backend, and the React web client.
- Implement reliable 1-click player verification via short-lived tokens generated by `/voice`.
- Stream positional telemetry efficiently (10-15 Hz) over authenticated WebSocket from Paper to the backend.
- Dynamically cull audio tracks and compute 3D binaural audio (HRTF) in the browser with sneaking whisper attenuation and underwater audio damping.
- Provide responsive Voice Activity Detection (VAD) with configurable thresholding to enable hands-free voice without background OS keybinding requirements.

**Non-Goals:**
- In-game native Push-To-Talk hotkey interception (browsers cannot intercept OS-level global keyboard events while Minecraft is the focused active window).
- Native radio/walkie-talkie items or global broadcast channels in this initial foundation change (reserved for future delta specs).
- Standalone desktop companion applications (focus remains strictly zero-install web client).

## Decisions

### Decision 1: Monorepo Project Layout
We organize the repository into three decoupled modules:
- `paper-plugin/`: Minecraft Paper plugin.
- `voice-server/`: Node.js / TypeScript backend service.
- `web-client/`: Modern SPA web frontend.

*Rationale*: Enables independent build and deployment lifecycles while keeping protocol schemas and shared constants aligned in a single repository.

### Decision 2: Paper Plugin Stack (Java 25 + Gradle Kotlin DSL)
The plugin targets Java 25 using Gradle with Kotlin DSL (`build.gradle.kts`) and the Paperweight/PaperMC API.
- *Alternatives considered*:
  - *Maven*: Standard in legacy plugins, but slower builds and more verbose configuration.
  - *Java 21 LTS*: Stable, but Java 25 provides the latest language features, pattern matching, and performance improvements requested by the server operator.

### Decision 3: Audio Transport via Mediasoup SFU
The voice backend implements Mediasoup as an in-process C++ worker SFU controlled by TypeScript.
- *Alternatives considered*:
  - *LiveKit*: Excellent high-level features, but requires maintaining a separate Go daemon or external service container.
  - *WebRTC Mesh (P2P)*: Bandwidth scales at O(N^2); completely collapses when multiple players gather in proximity.
  - *MCU (Server-side mixing)*: Extremely heavy server CPU requirements for spatial 3D encoding per listener.
- *Rationale*: Mediasoup runs directly within the Node.js process, offers microsecond routing latency, and allows dynamic track subscription control based on player block distances.

### Decision 4: Client-Side 3D Binaural Spatialization (Web Audio API)
Each peer audio stream is routed through a dedicated Web Audio graph:
```
[ MediaStreamTrack (Opus) ]
            |
            v
   [ MediaStreamAudioSourceNode ]
            |
            +--------------------------+
            |                          | (Normal)
            |                          v
            |             [ PannerNode (HRTF model) ]
            |                          |
            v (Underwater)             |
   [ BiquadFilterNode (LowPass) ]      |
            |                          |
            +------------+-------------+
                         |
                         v
                [ AudioContext.destination ]
```
- *Rationale*: Offloads all 3D trigonometric panning and HRTF convolution to the client's local audio hardware, saving substantial server computing power.

### Decision 5: Proximity Calculation and Telemetry Synchronization
The Paper plugin transmits batch coordinate updates at 10-15 Hz over WebSocket to the voice server:
- Coordinates: `x`, `y`, `z`, `yaw`, `pitch`, `world`, `isSneaking`, `isSubmerged`.
- The server checks Euclidean distance:
  - Standard conversation radius: 30 blocks.
  - Sneak (whisper) radius: 8 blocks.
  - Different dimensions: Immediate cut-off.
- The web client uses linear interpolation (Lerp) over 66-100ms intervals so listener spatial panning remains perfectly smooth without micro-stutter.

## Risks / Trade-offs

- **[Risk] Background Browser Audio Throttling** → Modern Chromium and Safari browsers may throttle background tabs when minimized.
  - *Mitigation*: The web client plays an active Web Audio stream and maintains an open WebRTC connection, which browser audio policies recognize as active real-time media and exempt from aggressive tab throttling.
- **[Risk] HTTPS Requirement for Microphone Access** → Browsers will refuse microphone permissions when accessed over plain HTTP (unless localhost).
  - *Mitigation*: The server configuration includes built-in reverse proxy documentation (Caddy/Nginx) and automatic local self-signed or Let's Encrypt support.
- **[Risk] NAT / Firewall Traversal for WebRTC** → Players behind restrictive symmetric NATs may fail direct UDP connection to the voice server.
  - *Mitigation*: The voice server configuration includes configurable STUN/TURN server endpoints and exposed UDP port range declarations.

## Migration Plan

1. Operators compile and drop `paper-plugin.jar` into the Paper server `plugins/` directory.
2. Operators deploy `voice-server` with `npm install` and configure `config.json` with the server URL, secret key, and port bindings.
3. Build the web client with `npm run build` or serve static assets directly from `voice-server`.
4. Paper plugin connects to `voice-server` upon boot; players type `/voice` to receive web links.
